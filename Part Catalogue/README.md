# BD BOM — structured part catalogue

Machine-readable extraction of the `BD BOM` sheet from the Frauscher FAdC R2 BOM
calculator, together with the per-location quantities booked against the
**NWR Jaipur–Sawai Madhopur** axle counter tender.

Generated by `extract.py` from:

| Source | Sheet | Rows |
|---|---|---|
| `BOM CAL/ABS V.1_2025-BRC with BD BOM.xlsm` | `BD BOM` | 4–144 |
| `BOM CAL/Yard V.1_2025-BRC with BD BOM.xlsm` | `BD BOM` | 4–144 |
| `BOM CAL/Handover BID Process Sheet Version 11.xlsx` | `10.  BOQ` | group labels only |

Catalogue version **1.5** (cell `B1` of the source sheet).

The two workbooks carry an **identical catalogue** in columns A–G — verified cell
by cell across all 141 rows. They differ only in the quantity block `H:BF` and its
`SUM` in `BG`. ABS covers 8 station locations, Yard covers 13.

## Files

| File | Shape | Contents |
|---|---|---|
| `parts.csv` | 141 rows | One row per part: identifiers, description, UOM, driver, totals |
| `quantities.csv` | long form | One row per part × project × location, non-zero only |
| `parts.json` | nested | Everything above plus source metadata and detected data issues |

## `parts.csv` fields

| Field | Meaning |
|---|---|
| `key` | Stable synthetic key, `BD` + source row (e.g. `BD041`). The sheet has no unique part key of its own |
| `sl_no` | Serial number, column A |
| `source_row` | Row in `BD BOM`, for traceability back to the workbook |
| `boq_group` | Outdoor / Indoor / Cubical / Reset / Switch / Misc / Tools — matched on part number against the handover BoQ. Blank where that sheet does not list the part (116 of 141) |
| `at_sales_cloud` | AT item code (Sales Cloud) |
| `in_sales_cloud` | IN item code (Sales Cloud) |
| `ramco_erp` | IN item code for RAMCO ERP |
| `rdso` | RDSO part number |
| `description` | Line item description, wrapping marker characters removed |
| `uom` | Unit of measure — populated for only 50 of 141 parts |
| `markers` | The `!`, `@`, `$` characters that wrapped the description in the source. **Preserved, not interpreted** — see below |
| `duplicate_code` | `yes` where a part number is shared with another catalogue row |
| `driver_type` | `gesamt` \| `derived_from_parts` \| `none` — where the quantity comes from |
| `driver_ref` | `Gesamt!row N`, or the sibling part keys it is computed from |
| `driver_label` | The `Gesamt` row label, i.e. the human name of the driver |
| `driver_formula` | The literal source formula, e.g. `=Gesamt!C39` |
| `qty_abs`, `qty_yard`, `qty_total` | Quantities booked on this tender |

## Provenance: 23 of 141 parts are calculated

This is the headline result of the extraction.

| `driver_type` | Count | Meaning |
|---|---|---|
| `gesamt` | 13 | Quantity is a direct link to a `Gesamt` rollup row, which is itself computed from the per-location rack layouts on sheets `01`–`30` |
| `derived_from_parts` | 10 | Quantity is arithmetic over sibling catalogue rows, e.g. `IN Rail claw = sensor 5 m + 10 m + 15 m` |
| `none` | **118** | No formula. The cell is blank, or a human types a number into it |

Only **20 parts carry a non-zero quantity** on this tender; the other 121 are
catalogue entries dormant on this project.

The 13 `gesamt`-driven parts are the entire automated core of the tool: wheel
sensor, BSI board, BGT07 rack, five backplane variants, PSC, COM-AdC, AEB and
IO-EXB. Everything commercially significant that is *not* in that list —
cubicles, reset boxes, reset cubicles, co-operation panels, line verification
boxes, FDS, switches, timers, relays — is typed by hand every tender.

## Known data issues in the source

Found while validating the extraction. All are faithfully represented in the
output rather than silently corrected.

**1. Duplicate location label (Yard workbook).** Columns `O` and `Q` are both
headed `Devpura Acc-2`, carrying different quantities (29 and 27 wheel sensors).
Cross-referencing `16.DP TS details` in the handover sheet — Devpura UP = 29,
Snaganer UP = 27 — column `Q` is Snaganer's second column, mislabelled by
copy-paste. Because of this, `quantities.csv` is keyed by `location_col`, not by
location name; a name-keyed extract silently loses one column's worth of every
quantity in the workbook.

**2. Ten duplicate part numbers across four numbering systems.**

| Part number | Rows | Note |
|---|---|---|
| `100383`, `100384` | BD063/BD066, BD064/BD067 | *Rail claw* SK140-011/-012 and *rail claw plate* SK140-011/-012 share codes — these are different physical items |
| `110279` | BD070, BD086 | `COM-FSFB101 GS04` vs `COM-FSE101 GS04` |
| `101424` | BD057, BD099 | Same connection cable listed twice |
| `102661`, `102662` | BD080/BD093, BD081/BD094 | Prewired 20U half cubicle, 1 BGT and 2 BGT, listed twice each |

**3. Undocumented marker characters.** 25 descriptions are wrapped in `!`, `@`
or `$`, sometimes combined (`! $ SK140-013 … $ !`). The workbook contains no
legend, no cell comment and no distinguishing fill or font for them, so no
meaning is asserted here. They are stripped from `description`, kept verbatim in
`description_raw`, and reported in `markers`.

**4. 91 of 141 parts have no unit of measure.**

## Validation

Two independent checks, both re-runnable via `validate.py`:

1. **Internal.** Sum of per-location quantities equals the workbook's own `BG`
   total — agrees for all 141 parts across both projects.
2. **External.** Catalogue totals against the handover sheet's `10.  BOQ`,
   matched on part number: 25 lines match on code, **16 identical**. The 9
   differences are structural, not extraction errors, and fall into two groups.

**Kit versus component representation.** The handover BoQ books the trackside
scope as three bundled kit codes; the calculator books the same scope as six
separate component lines:

| | Handover BoQ | Calculator |
|---|---|---|
| `102058` kit, 4.8 m tube | 350 | — |
| `101880` kit, 9.8 m tube | 163 | — |
| `102428` kit, 14.8 m tube | 37 | — |
| | **550** | |
| Wheel sensor RSR180 5 m | — | 550 |
| IN Protection tube 4.8 m | — | 550 |
| Rail claw SK140-011 + plate | — | 550 each |
| Clamping bolt BBIK M12-22 | — | 550 |
| Rail deflector FRD001 | — | 550 |

Both sides total 550 detection points, matching `550 DP as per NIT` in the
project questionnaire. Note that the calculator assumes **all 550 runs take the
4.8 m tube** (rows for 9.8 m and 14.8 m compute to zero), while the BoQ splits
them 350 / 163 / 37 by actual cable run length. That split is applied by hand,
downstream, and nothing feeds it back into the calculator.

**Hand-typed-only lines.** Six parts carry a quantity in the handover BoQ and
zero in the calculator, because no rule produces them: Line Verification Box
(189), Reset box (315), Axle counter cubicle FAR-002 (22), Reset cubicle (16),
Co-operation reset panel (11), FDS102 (12).

## Caveats

- **No prices.** The `Preisliste` sheet in both workbooks is entirely zeros and
  its exchange-rate row is dated 2015-08-07. Rates live in
  `V.1_Cost Estimation_Template_Rev15.xlsx`, referenced as an external link to a
  local `F:\` path. No commercial data is included here.
- Quantities are the **cached values** Excel last wrote. They were not
  recalculated, since the workbooks link to a file on a personal OneDrive that is
  not reachable from here.
- `boq_group` is populated only where the handover BoQ lists the part. The
  `BD BOM` sheet itself has no grouping column.
